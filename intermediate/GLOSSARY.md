# Intermediate Python Glossary

A quick reference for the terms used across the 20 lessons.

| Term | Definition |
|---|---|
| Abstract interface | A description of behavior expected from an object, without committing to one concrete implementation. |
| Annotation | A type hint attached to a variable, argument, or return value. Python does not automatically enforce it. |
| API | An interface through which software components exchange requests and responses. |
| CLI | Command-line interface: a tool operated through terminal commands and arguments. |
| Closure | A function retaining access to values from the enclosing scope after the enclosing call returns. |
| Composition | Building an object using other objects as collaborators rather than subclasses. |
| Context manager | An object controlling setup/cleanup through the with statement. |
| Dataclass | A class with automatically generated initialization and other record-oriented methods. |
| Decorator | A callable that receives a callable or class and returns a modified/replacement object. |
| Dependency injection | Passing a collaborator into a component instead of constructing it internally. |
| Duck typing | Using an object according to supported behavior rather than its specific declared class. |
| ETL | Extract–Transform–Load, a structured approach to moving and reshaping data. |
| Generator | An iterator created by a generator function or expression, producing values lazily. |
| HTTP | Request/response protocol used by web APIs. |
| Idempotency | Repeating an operation has the same intended effect as performing it once. |
| Iterator | An object supplying successive values through __next__ until StopIteration. |
| Iterable | An object from which an iterator can be obtained through iter(). |
| Lazy evaluation | Delaying computation until its result is requested. |
| Mock | A test double that stands in for a dependency and can record interactions. |
| ORM | Object-relational mapping; an abstraction for mapping application objects to relational data. |
| Parameterized SQL | SQL with bound values rather than concatenated untrusted data. |
| Polymorphism | Calling common behavior through objects with different implementations. |
| Profiling | Measuring where an application's execution time or memory is spent. |
| Protocol | A typing construct describing required methods or attributes by structure. |
| Pure function | A function whose result depends only on its inputs and has no observable side effects. |
| Schema | A description of expected data structure, fields, or constraints. |
| Static type checker | Tool that analyzes type annotations without executing the application. |
| Transaction | A set of database operations committed or rolled back as a unit. |
| TypedDict | Typing construct describing expected keys and value types of dictionary-shaped data. |
| Unit test | A test checking one focused behavior in isolation. |
